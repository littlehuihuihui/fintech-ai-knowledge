# Data Nexus · 知识点主树规则

> **适用**：全平台 7 棵知识树（SQL / BI / Python / 数据库 / ML / ETL / DWH）  
> **目的**：同一知识点只在一棵「主树」讲透；从树只保留本领域必需的切片，避免重复建设与口径漂移。  
> **权威关系图**：见下文对照表；各树根节点「与相邻树的关系」章节必须与本文件一致。

---

## 1. 规则说明（为什么需要主树）

### 1.1 问题

跨树会出现同一概念多处展开，例如：

| 知识点 | 曾出现于 |
|---|---|
| 幂等 | SQL / ETL / DWH |
| SCD | ETL / DWH |
| 分区 | SQL / ETL / DWH / 数据库 |
| 事务 / 隔离 | SQL / 数据库 |
| 索引 | SQL / 数据库 |

学习者不知道「以哪棵为准」，从树又容易把主树内容复制粘贴一遍，造成：

1. **内容重复**：维护成本翻倍，改正一处漏改另一处。  
2. **口径不一致**：例如幂等在 SQL 写成 UPSERT 语法课，在 ETL 写成作业语义课，两边数字对不上。  
3. **学习路径混乱**：同一主题在多树各学一遍，无法形成「主路径 → 邻域切片」的心智模型。

### 1.2 原则

1. **一知识点一主树**：概念定义、完整机制、验收标准只在主树叶讲义维护。  
2. **从树只保留切片**：从树可以保留「业务侧怎么用 / 本领域步骤 / 语法备注」，但必须显式指向主树，不重写完整理论。  
3. **不删节点**：历史节点与导航结构保留；治理靠「主从声明 + 内容边界」，不是删树。  
4. **根节点公示**：每棵树的 `*-root` 必须有「与相邻树的关系」，列出本树作主 / 作从的知识点。  
5. **指标口径另册**：跨树指标字段映射以 SQL 宪法页「全平台指标口径映射表」为准；本文件只治理「知识点主从」，不替代指标口径。

### 1.3 如何使用

| 角色 | 动作 |
|---|---|
| 学习者 | 遇重复主题，先学**主树**对应叶课，再看从树切片如何落地到本领域。 |
| 作者 / 架构师 | 新增或加厚叶讲义前，先查本表；属从树则只写「只保留」列允许的内容。 |
| 评审 | 发现从树出现完整机制长文 → 打回，要求收敛为切片 + 主树链接。 |

## 2. 主树 / 从树对照表（5 个已识别重复点）

| 知识点 | 主树 | 从树 | 从树只保留 |
|---|---|---|---|
| 事务 / 隔离 / 锁 | **数据库** | SQL | 只保留业务侧事务写法（`BEGIN/COMMIT/ROLLBACK`、支付与事件同事务等） |
| 索引 / EXPLAIN / 统计信息 | **数据库** | SQL | 只保留业务侧索引改写（过滤列、避免函数套列、`EXPLAIN` 读计划结论） |
| 增量 / CDC / 幂等写入 | **ETL** | SQL、DWH | SQL 只保留 UPSERT 语法；DWH 只保留分区回刷（重跑某 `dt` 分区） |
| SCD / 缓慢变化维 | **DWH** | ETL | 只保留日批闭链步骤（开链/闭链作业顺序），不重复讲维表理论全文 |
| 分区 / 裁剪 | **DWH** | ETL、数据库 | ETL 只保留分区覆盖写入；数据库只保留分区表 DDL |

> **说明**：BI / Python / ML 当前未列入上表 5 点的主从冲突；若后续出现等价主题，按「机制在主树、用法在从树」增补本表，并同步改根节点章节。

## 3. 每个知识点：从树只保留什么（展开）

### 3.1 事务 / 隔离 / 锁

- **主树（数据库）**：隔离级别、锁类型、脏读/不可重复读/幻读、死锁、连接与会话边界。  
- **从树（SQL）只保留**：业务脚本里的事务块写法；「支付状态 + 事件日志必须同事务」类案例；**不**展开隔离级别矩阵全文。

### 3.2 索引 / EXPLAIN / 统计信息

- **主树（数据库）**：B-Tree / 选择性、覆盖索引、统计信息、执行计划读法。  
- **从树（SQL）只保留**：查询改写与索引友好写法（过滤下推、避免 `WHERE f(col)`）；读 `EXPLAIN` 结论用于改 SQL；**不**把引擎内部实现当本树主课。

### 3.3 增量 / CDC / 幂等写入

- **主树（ETL）**：增量窗口、CDC 语义、作业幂等、重跑策略、 Exactly-once / at-least-once 业务含义。  
- **从树（SQL）只保留**：`MERGE` / `INSERT … ON CONFLICT` / `UPSERT` 语法与业务键。  
- **从树（DWH）只保留**：按分区回刷（删除/覆盖某 `dt` 再写入）；**不**在 DWH 重写整套 CDC 理论。

### 3.4 SCD / 缓慢变化维

- **主树（DWH）**：SCD1/2/3、代理键、生效区间、拉链表语义与验收。  
- **从树（ETL）只保留**：日批闭链的作业步骤（何日闭链、何日开新链、失败回滚顺序）；理论与建模细节回指 DWH。

### 3.5 分区 / 裁剪

- **主树（DWH）**：分区策略、裁剪、与调度/回刷的关系、查询侧如何命中分区。  
- **从树（ETL）只保留**：分区覆盖写入（写哪一区、如何幂等覆盖）。  
- **从树（数据库）只保留**：分区表 DDL / 本地分区语法；分析型裁剪与数仓分区语义以 DWH 为准。

## 4. 按树速查（作者用）

| 树 | 本树为主的知识点 | 本树为从、须收敛的知识点 |
|---|---|---|
| 数据库 | 事务/隔离/锁；索引/EXPLAIN/统计信息 | 分区（相对 DWH）：只保留分区表 DDL |
| ETL | 增量/CDC/幂等写入 | SCD（相对 DWH）：只保留日批闭链步骤；分区：只保留分区覆盖写入 |
| DWH | SCD；分区/裁剪 | 增量/CDC/幂等（相对 ETL）：只保留分区回刷 |
| SQL | （上表 5 点均不为 SQL 主树） | 事务写法切片；索引改写切片；UPSERT 语法切片 |
| BI | — | 指标口径见 SQL 宪法映射表；机制类不与上表抢主树 |
| Python | — | 与四表样例对齐；机制类不与上表抢主树 |
| ML | — | 特征/样本可引用数仓与 SQL 口径；不与上表抢主树 |

## 5. 变更纪律

1. 修订本文件后，同步检查 7 个 `*-root` 的「与相邻树的关系」是否仍一致。  
2. 禁止在从树叶讲义中新增「完整机制」长文；评审清单见 §1.3。  
3. 不删除现有节点；若从树节点标题像主课，用导读/切片改写边界，而不是删 ID。
